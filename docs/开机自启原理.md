# 为什么之前「关掉 DSH 就失效」

## 根因

不是自启配置错了，而是**进程挂在错误的父子树上**。

Windows 的进程不是孤立的：`CreateProcess` 时子进程默认落在父进程的 **Job Object** 里。
终端类程序（DSH、cmd、Windows Terminal、VS Code 集成终端）都给自己建了 Job Object，
目的是"关掉终端时连带杀掉它启动的东西"，避免留孤儿进程。

于是出现：

```
DSH (进程树根)
 └─ node.exe (supervisor)   ← 我测试时从 DSH 的 bash 里启动的
     └─ node.exe (server)
```

DSH 一退出 → Job Object 销毁 → 整棵树被终止 → 日志里连「服务退出」都没来得及写。

**证据**：`out/supervisor.log` 最后一条停在 `2026-11-04T00:09:39` 的「已启动」，
之后没有任何「服务退出」记录就消失了 —— 被强杀才会这样。

## 修复

让进程脱离任何宿主的 Job Object。三个层次：

| 入口 | 父进程 | 是否受 DSH 影响 |
| --- | --- | --- |
| 从 DSH bash 启动 | bash → DSH | ❌ 会死（错误做法） |
| 启动文件夹 / 注册表 Run | explorer.exe | ✅ 不会（explorer 与 DSH 无关） |
| WMI `Win32_Process.Create` | WmiPrvSE.exe | ✅ 不会（服务进程） |

**关键点**：`explorer.exe` 和 DSH 是平级的独立进程，各自有各自的 Job Object。
DSH 关掉只销毁 DSH 那一棵，explorer 那一棵不受影响。

## 验证方法

看 supervisor 的**父进程是否已退出**：

```powershell
$procs = Get-CimInstance Win32_Process
$sup = $procs | Where-Object { $_.Name -eq 'node.exe' -and $_.CommandLine -match 'supervisor' } | Select-Object -First 1
$parent = $procs | Where-Object { $_.ProcessId -eq $sup.ParentProcessId }
if ($parent) { "父=$($parent.Name)#$($parent.ProcessId)  仍在" }
else { "父进程已退出 → supervisor 已脱离，DSH 动不到它" }
```

实测结果：

```
supervisor PID=36420  父=(已退出/已脱离)
```

父进程（explorer / wscript / WMIC 启动器）早已退出，supervisor 照常活着并守着 server。
**这就是脱离成功的铁证**：父死子活。

## 最终的启动链

```
explorer.exe  (登录时加载启动文件夹快捷方式 / 注册表 Run)
 └─ wscript.exe  (后台启动.vbs，隐藏，零窗口)
     └─ node.exe watchdog   (src/watchdog.js, windowsHide, 单实例, 长驻)
         └─ node.exe supervisor  (detached, 崩溃自动重启)
             └─ node.exe server  (--no-open, 永不打开浏览器)
```

**全程零窗口、零闪烁**。三个曾经导致「后台一直弹窗」的元凶，逐一消除：

| 元凶 | 症状 | 修复 |
| --- | --- | --- |
| `sh.Exec("cmd /c netstat …")` | 每执行一次闪一个 cmd 黑窗 | 改用 `MSXML2.XMLHTTP` 纯进程内探活 |
| PowerShell watchdog（`-WindowStyle Hidden`） | 创建瞬间仍会闪窗 | watchdog 改写成 **Node 版**，`windowsHide:true` 完全不可见 |
| `server.js` 默认 `OPEN = !--no-open` | 手动/异常路径会弹浏览器 | 反转为 `OPEN = --open`，**只有显式传参才开** |

每一环都**故意脱离上一环**，任何一环死掉都不影响下面已启动的服务：

| 环节死掉 | 影响 |
| --- | --- |
| DSH 关闭 | 无（根本不在这条链上） |
| explorer 重启 | 无（wscript 已独立） |
| wscript 退出 | 无（watchdog 已独立） |
| watchdog 被杀 | 服务仍活着；下次登录会重新拉 watchdog |
| supervisor 崩溃 | watchdog 60 秒内重新拉起 |

实测证据（杀掉 watchdog 后）：

```
root=200  api=200     ← 服务照常
supervisor #34568     ← 仍然活着
```

完整重启实测（模拟登录）：

```
root=200  api=200
watchdog   #44356
supervisor #46032
server [no-open] #39276   ← 确认不会弹浏览器
```

## 三个自启入口

配置齐了，任一生效（同时存在时靠文件锁让位，不会起两份）：

1. **启动文件夹**
   `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\AI-Token统计台.lnk`
   → `wscript.exe "…\后台启动.vbs"`

2. **注册表 Run**
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\AITokenDashboard`
   → 同上

3. **手动 / 应急**
   双击 `后台启动.vbs`

## 单实例保证

`src/watchdog.js` 用**原子独占锁** `out/.watchdog.lock`
（`fs.openSync(LOCK, 'wx')`，文件已存在则创建失败）保证全局只有一个 watchdog：

```
2026-11-4 22:17:13  WATCHDOG 启动 (port=8787 间隔=60s pid=38984)
2026-11-4 22:17:13  端口 8787 无监听 -> 拉起 supervisor
2026-11-4 22:17:13    已拉起 PID=44380
```

> 试过的三种方案：
> 1. `Named Mutex + WaitOne(0)` —— 多会话下两个实例都"拿到锁"，失败
> 2. `FileStream(FileShare.None)` —— PowerShell 下不稳定
> 3. `openSync('wx')` —— 原子创建，语义最明确，**最终采用**

## 排查清单

| 症状 | 检查 |
| --- | --- |
| 服务没起来 | `out/vbs-launch.log` 有没有 START 行 |
| 起来了又没了 | `out/supervisor.log` 有没有「服务退出」；没有=被强杀 |
| watchdog 是否在 | `out/watchdog.log` 最近一行；或查 node.exe 且命令行含 `watchdog.js` |
| 端口占用 | `netstat -ano \| findstr :8787` |
| 确认已脱离 | 见上一节「验证方法」 |
| **后台一直弹窗** | 确认无 `cmd /c netstat`、无 `powershell -File watchdog.ps1`（见下表） |
| 想换端口 | 改 `后台启动.vbs` 里 `HttpAlive(8787)` 的数字 |

### 弹窗来源自查

```powershell
# 1) 不该有 cmd netstat（旧版闪烁源）
Get-CimInstance Win32_Process -Filter "Name='cmd.exe'" |
  Where-Object { $_.CommandLine -match 'netstat' }

# 2) 不该有 PowerShell watchdog（旧版闪窗源）
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
  Where-Object { $_.CommandLine -match 'watchdog\.ps1' }

# 3) server 必须无 --open
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -match 'server\.js' } |
  ForEach-Object { if ($_.CommandLine -match '--open') { '有 --open，会弹浏览器！' } else { 'OK 无 --open' } }
```

三项都应返回空 / OK。

## 验证命令（一条搞定）

```powershell
# 服务健康
curl.exe -s -o NUL -w "root=%{http_code}`n" http://127.0.0.1:8787/
curl.exe -s -o NUL -w "api=%{http_code}`n"  http://127.0.0.1:8787/api/data

# 真实 watchdog 数（注意别把查询语句自身算进去）
(Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
  Where-Object { $_.CommandLine -match 'watchdog\.ps1' }).Count

# 父进程是否已退出
$p = Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
     Where-Object { $_.CommandLine -match 'supervisor' } | Select-Object -First 1
$parent = Get-CimInstance Win32_Process -Filter "ProcessId=$($p.ParentProcessId)"
if (-not $parent) { "已脱离（父进程已退出）" } else { "父=$($parent.Name)" }
```
