# AI Token 消耗统计台

本机所有 AI Agent 的 token 用量归集看板。纯本地、零依赖、离线可用。

## 怎么打开

| 方式 | 操作 | 说明 |
| --- | --- | --- |
| **常驻（推荐）** | 双击 `设置开机自启.bat` | 开机自动后台运行，**不弹窗口、不依赖 DSH**；然后浏览器打开 `http://127.0.0.1:8787/` |
| 临时打开 | 双击 `启动网页端.bat` | 起一次服务并自动开浏览器，关窗口即停 |
| 离线快照 | 双击 `更新数据.bat` | 重采数据后直接双击 `index.html`，不需要任何服务 |

> 常驻模式下服务由守护进程管理：崩了自动重启，端口已有实例时新实例安静退出，不会打架。

## 开机自启 / 常驻运行

**不依赖 DSH**：项目自带 `bin/node.exe`（独立运行时），DSH 关着、甚至卸载了都不影响。

> ⚠️ **本仓库不含 `bin/node.exe`**（约 90MB，超出仓库体积合理范围，已在 `.gitignore` 中排除）。
> 首次使用前请自己准备运行时，二选一：
>
> - **方式 A（推荐）**：把官方 Node.js 的 `node.exe` 复制到 `bin/node.exe`，`bin/` 目录需手工新建。
> - **方式 B**：安装系统级 Node.js（≥18），把所有 `.bat` / `.vbs` 里的 `bin\node.exe` 改成 `node`。
>
> 未放置运行时的情况下，`demo/demo-index.html` 仍可直接双击打开浏览脱敏演示数据，只是跑不起来采集与常驻。

### 开启

双击 **`设置开机自启.bat`**，它会做三件事：

1. 在启动文件夹写快捷方式（`%APPDATA%\...\Startup\AI-Token统计台.lnk`，`wscript.exe` 调用 `后台启动.vbs`，窗口样式 7 = 最小化）
2. 在注册表写 Run 项（`HKCU\...\Run\AITokenDashboard`）作双保险
3. 立即启动一次（已在运行则跳过）

### 关闭

| 需求 | 操作 |
| --- | --- |
| 取消开机自启 | 双击 `取消自启.bat`（删快捷方式 + 删注册表项） |
| 只停当前服务 | 双击 `停止服务.bat` |
| 临时启动一次 | 双击 `后台启动.vbs` |

### 运行状态与排查

| 项 | 位置 |
| --- | --- |
| 服务地址 | <http://127.0.0.1:8787/> |
| 守护日志 | `out\supervisor.log`（超 2MB 自动切成 `.1`） |
| 进程 | `bin\node.exe` 跑 `src\supervisor.js` 与 `src\server.js` |
| 确认走的是内置 node | 任务管理器看进程路径应为 `…\AI-Token统计台\bin\node.exe` |

**自愈行为**：server 异常退出 → 守护进程退避重启（2s 起，最长 30s）；连续稳定运行 10 分钟后退避重置。
**多实例**：重复自启或手动再开，新实例发现端口已有统计台会**正常退出**（exit 0，不触发重启），日志留一条记录。

### 换端口

改 `后台启动.vbs` 里的启动命令或在 `设置开机自启.bat` 中给 supervisor 传 `--port`，例如：

```
... bin\node.exe ...\src\supervisor.js --port 8899
```

## 数据从哪来

| 来源 | 路径 | 作用 |
| --- | --- | --- |
| DSH 用量账本（主源） | `~/.dsh/dsh-bottom-info-bar/usage-ledger.sqlite` | 逐请求明细：provider / model / sessionId / input / cacheRead / cacheWrite / output / cost |
| DSH 会话日志 | `~/.dsh/sessions/**/session.v4.jsonl.zstd` | 会话标题、工作区、主代理/子代理身份、轮次与步数 |
| 旧版 JSON 账本 | `~/.dsh/dsh-bottom-info-bar/usage-records.json` | 仅在 sqlite 缺失时兜底 |
| 外部 Agent（可选） | `extra-agents/*.json` | 手工追加其它工具的用量，格式见下 |

采集只读，不改动任何 Agent 数据。会话日志是**多帧 zstd**（一个会话文件可能上万帧），`src/aggregate.js` 里自带逐帧解压实现，不依赖系统 zstd。

### 性能

| 场景 | 耗时 | 说明 |
| --- | --- | --- |
| 冷启动（无缓存） | ~3.0 s | 解压 68 MB / 12k+ 帧会话日志 |
| 热启动（缓存命中） | ~0.36 s | 只用 `size+mtime` 判断是否变化 |
| 会话正在写入 | 增量 | 从上次解到的**帧偏移**继续，不重复解压前缀 |

解析结果缓存在 `out/.session-cache.json`（可随时删除，删了只是下次全量解）。服务端 `/api/data` 带 ETag，内容未变返回 304，省掉 120 KB 传输；并发请求共享同一次聚合。

### 追加其它 Agent 的用量

在 `extra-agents/` 放任意 `*.json`，数组或 `{records:[...]}` 均可，单条记录：

```json
{"ts": 1793722000000, "provider": "cursor", "model": "gpt-5",
 "sessionId": "my-session-1", "input": 12000, "cacheRead": 0,
 "cacheWrite": 0, "output": 400, "cost": 0.03, "pricingStatus": "priced"}
```

## 页面讲什么

- **总计** — 累计 token、输入 / 缓存复用 / 输出三段拆分、请求数、Agent 数、缓存命中率、日均、单次平均、峰值单日、已计价成本、未定价条数。
- **每日** — 堆叠柱图 + **7 日移动平均趋势线**；可切「按 Agent / 按类型」，7 / 14 / 30 / 全部天；点图例可开关序列（隐藏项变灰仍在，可点回来）；无记录的日留空并标橙色虚线，悬停显示邻近日对比。
- **每月** — 月累计条 + 请求数、输入、缓存、输出、有记录天数、成本，当月亮酸绿高亮。
- **活跃时段** — 周 × 小时热力图。
- **Agent 明细** — 可排序（点表头或 Enter/Space）、可搜索、按角色筛选，展示请求数、输入、缓存读、输出、合计、占比、最近活动；未归档会话额外标注「模型 · 活跃区间」便于辨认。
- **模型供应方 / 模型排行 / 会话 Top** — 按用量排序。
- **数据来源** — 每个源是否读到、多少条、路径，以及会话缓存复用 / 增量 / 全解数量。

## 交互与可达性

- 图例、分段控件、可排序表头都是真实可聚焦控件，支持键盘操作（`Tab` 导航、`←/→` 切换分段、`Enter/Space` 切换图例与排序）。
- 切换后焦点保持在原控件上，不会被重绘打断。
- 尊重 `prefers-reduced-motion`。

## 成本怎么算

价格取自官方价目表（`src/pricing.js` 内置，来源 <https://api-docs.deepseek.com/zh-cn/quick_start/pricing>，抓取于 2026-11-04），单位 **元 / 百万 tokens**。

**错峰规则（官网原文）**：空闲时段价格 = 高峰时段的一半。北京时间 **周一至周五（不含法定节假日）9:00–12:00、14:00–18:00** 为高峰；**其余时段、周末及法定节假日全天空闲**。

| 模型 | 输入·命中缓存 | 输入·未命中 | 输出 |
| --- | --- | --- | --- |
| deepseek-flash | 0.02 → 0.04 | 1 → 2 | 4 → 8 |
| deepseek-v4-pro | 0.15 → 0.30 | 4.5 → 9 | 13.5 → 27 |

（`→` 右侧为高峰价）

**两种数据来源，不混合：**
- 账本里 `pricingStatus=priced` 的记录（本期 **9,993** 条）：直接采信官方算出来的金额，不重算。
- 其余未定价记录（本期 **15,510** 条）：用同一套官网规则补算。

**可信度自检**：拿 9,993 条官方已计价记录，用本程序的单价 × 时段规则逐条反算，**9,993 条全部精确吻合，0 条不符**；反过来用最小二乘反解单价，得到的正是上表数值（误差 0）。所以补算部分与官方口径一致。

**本期结果**（覆盖 2026-10-10 → 11-04）：

| 指标 | 值 |
| --- | --- |
| 累计成本 | **¥1,217** |
| 高峰时段 | ¥193.47 / 2,046 次 / 662.5M tokens |
| 空闲时段 | ¥1,023 / 23,457 次 / 3.49B tokens |
| 错峰节省 | **¥1,023（46%）**，若全按高峰价需 ¥2,240 |
| 每请求均价 | ¥0.05 |
| 综合单价 | ¥0.29 / 百万 token（含缓存折扣） |

> 成本是**推算值**，实际扣费以官方账单为准。网页搜索 / 抓取（Search、Fetch）按次计费，不在 token 成本内。

## 隐私与发布

**本机采集产物永不入库**（`.gitignore` 已排除 `data.json` / `data.js` / `out/` / `bin/` / `extra-agents/*.json`）。

提交前有两道强制关卡：

```bash
# 1) 扫描源码 + demo 的敏感模式，校验 demo 结构
node tools/audit-privacy.js

# 2) 以 git 视角扫描「暂存区」全部内容，并检查排除清单与大文件
bash tools/pre-commit-gate.sh
```

检测覆盖：本机用户名、Windows 绝对路径、IM 账号身份、真实话题与工作区名、凭据字样、API Key / JWT / GitHub Token / 手机号 / 邮箱形态。

**检测脚本会跳过自身**（它们含规则字符串），但对其余所有文件保持严格。

### 安装提交前钩子（可选，一次即可）

```bash
mkdir -p .git/hooks
cat > .git/hooks/pre-commit <<'EOF'
#!/bin/sh
bash tools/pre-commit-gate.sh || exit 1

chmod +x .git/hooks/pre-commit
```

## 口径

- **合计 = 输入 + 缓存读取 + 缓存写入 + 输出**。缓存命中会显著放大总量，这是各家控制台的口径。
- Agent 身份：有会话日志的按**会话**计（同一工作区多个会话加短 ID 区分）；日志已归档但账本仍留痕的标为**未归档会话**；无会话 ID 的归为**散记请求**。
- 成本只在价目表可匹配时给出，未定价请求只累计 token 不计钱。
- 日 / 月按 `Asia/Shanghai` 切分。
